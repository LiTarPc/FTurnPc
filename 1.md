# Интеграция sing-box в FTurnPc

**Цель:** добавить в FTurnPc второй сетевой движок на базе sing-box, чтобы приложение умело работать
в TCP-режиме — VLESS (в т.ч. Reality / Vision / WS / gRPC), Trojan, VMess, Shadowsocks — сохранив
существующий движок FreeTurn, UI, трей, логи и статистику.

Проверено по: репозиторий `LiTarPc/FTurnPc` (Wails v2 + Go + React), sing-box **v1.14.0** (актуальный
стабильный релиз на 12.09.2026; предыдущая линия — 1.13.21).

---

## 0. Итог в двух абзацах

Сейчас FTurnPc — это оболочка вокруг одного движка: процесс `freeturnclient.exe` поднимает UDP-туннель
на `127.0.0.1:9000`, а приложение само создаёт userspace-WireGuard (`wireguard-go` + Wintun,
интерфейс `wg-turn`) и вручную рулит маршрутами, DNS и обходами через `netsh`.

sing-box закрывает весь этот слой целиком: он сам создаёт TUN-интерфейс, сам ставит маршруты
(`auto_route`), сам защищает от DNS-утечек (`strict_route`, `dns_mode`), сам умеет обход по GeoIP
(`route_exclude_address_set` + уже лежащий в репозитории `geoip-ru.srs`) и сам реализует VLESS/Trojan/
VMess/SS поверх TCP. Поэтому правильная интеграция — **не «прикрутить sing-box к WireGuard-стеку»,
а сделать второй движок, полностью параллельный FreeturnEngine**, который выбирается по типу профиля.
Общими остаются: Orchestrator, трей, окно логов, статистика по счётчикам интерфейса, авто-реконнект,
MTU/MSS и NAT-диагностика.

## 1. Что есть сейчас (карта кода)

| Файл | Роль | Судьба при sing-box |
|---|---|---|
| `backend/orchestrator.go` | загрузка профиля, лог-врайтер, авто-реконнект, `ConnectParams`/`ProfileData` | **правим**: выбор движка, поле `engine`, интерфейс `Engine` |
| `backend/engine_freeturn.go` | запуск `freeturnclient.exe`, аргументы, ожидание выхода | остаётся как есть |
| `backend/engine_parser.go` | парсинг stdout FreeTurn, детект готовности DTLS → подъём WG | остаётся; аналог пишем для sing-box |
| `backend/engine_stats.go` | опрос `getInterfaceBytes(wgIface)` раз в секунду → события `stats` | **переиспользуем** (меняем имя интерфейса на переменную) |
| `backend/windows_wg.go` | Wintun + `wireguard-go` + `netsh` адрес/MTU/маршруты | **не используется** для sing-box-профилей |
| `backend/windows_routes.go` | `applyExcludeRoutes`, `AddBypassRoute`, VK/RU CIDR через `netsh -f` | **не используется**: делает sing-box |
| `backend/windows_dns.go` | NRPT-правила против DNS-утечек, чистка «хвостов» | **не используется**: `strict_route` + `dns_mode` |
| `backend/common_wg.go` | парсер wg-конфига, `mergeCIDRs`, `loadGeoIPRuCIDRs` | **переиспользуем `loadGeoIPRuCIDRs` + `mergeCIDRs`** для inline rule-set |
| `backend/core_update.go` | проверка/скачивание/замена ядра `freeturnclient` | **расширяем**: второе ядро `sing-box.exe` |
| `backend/nat_check.go` | STUN-диагностика типа NAT | остаётся (работает через любой туннель с UDP) |
| `backend/app.go` | биндинги Wails для фронта | **правим**: `ParseLink`, `SingboxVersion`, `UpdateSingbox` |
| `frontend/src/lib/utils/wdttLink.ts` | парсер `freeturn://` / `wdtt://` / `[Interface]` | **расширяем**: `vless://`, `trojan://`, `vmess://`, `ss://` |
| `frontend/src/lib/types.ts`, `store.ts` | модель `Server`, localStorage | **правим**: `engine`, `outbound` |
| `project/geoip-ru.srs`, `assets/freeturn/geoip-ru.srs` | **уже готовый бинарный rule-set sing-box** (магия файла `SRS\x01`) | **используем как есть** |

Полезное наблюдение: `geoip-ru.srs` в репозитории — это ровно тот формат, который sing-box ест
как `{"type":"local","format":"binary","path":"geoip-ru.srs"}`. Половина работы по «Обходу RU» уже
лежит в проекте.

## 2. Три способа интеграции: что выбрать

### Вариант A — внешний бинарь `sing-box.exe` + JSON-конфиг ✅ рекомендуемый старт

Приложение генерирует `config.json`, запускает `sing-box.exe run -c config.json -D <dataDir>`,
читает его stdout/stderr, ловит строку `sing-box started`, дальше — статистика по счётчикам TUN.

* **Плюсы:** архитектурно совпадает с тем, что уже сделано для `freeturnclient.exe` (тот же
  `exec.CommandContext`, тот же парсер логов, тот же `core_update.go` для обновления ядра);
  обновление ядра без пересборки приложения; проблемы sing-box не роняют GUI; сборка Wails
  не усложняется вообще.
* **Минусы:** +21…33 МБ отдельным файлом в поставке, IPC через логи, нужна аккуратная
  остановка процесса (см. §5.3).
* **Трудозатраты:** 2–4 дня.

### Вариант B — sing-box как Go-библиотека (один exe)

`import "github.com/sagernet/sing-box"` и запуск `box.New(...)` внутри процесса приложения.

* **Плюсы:** один исполняемый файл, логи и статистика напрямую через Go API
  (`PlatformLogWriter`, Clash-менеджер трафика), нет проблем с зомби-процессами и правами.
* **Минусы:** размер FTurnPc.exe вырастает на ~30–40 МБ; тянется большой граф зависимостей
  (gvisor, quic-go, utls, tailscale…); **обязательны build-теги и `-ldflags "-checklinkname=0"`**;
  sing-box требует Go ≥ 1.25.5 (в проекте уже 1.26 — ок); при апдейте ядра нужно пересобирать всё
  приложение; лицензия sing-box — GPLv3, у FTurnPc тоже GPLv3, конфликта нет.
* **Трудозатраты:** +2–3 дня после варианта A (движок и генератор конфига переиспользуются на 90 %).

### Вариант C — унификация: перевести и FreeTurn на sing-box

sing-box умеет `endpoint: wireguard`, поэтому текущий FreeTurn-профиль выражается так:
TUN inbound → WireGuard-endpoint с `peers[0].address = 127.0.0.1`, `port = 9000` → готово.
Тогда `wireguard-go`, `windows_wg.go`, `windows_routes.go`, `windows_dns.go` (≈ 800 строк
платформенного кода) удаляются, а маршруты/DNS/статистика становятся одинаковыми для обоих
профилей. Делать это стоит **только после** того, как вариант A/B заработает и обкатается
(см. §9).

### Рекомендация

Фаза 1–3 — вариант A. Фаза 4 — переезд на вариант B, если хочется «один exe».
Вариант C — отдельная задача-рефакторинг, не смешивать с добавлением VLESS.

## 3. План по фазам

| Фаза | Что делаем | Файлы | Результат |
|---|---|---|---|
| 1 | Модель данных и парсер ссылок | `backend/link_parse.go`, `orchestrator.go`, `frontend/.../wdttLink.ts`, `types.ts` | `vless://…` превращается в профиль и сохраняется |
| 2 | Генератор `config.json` | `backend/singbox_config.go` (+`_test.go`) | из профиля получается валидный конфиг, `sing-box check` проходит |
| 3 | Движок + оркестратор + UI | `backend/engine_singbox.go`, `orchestrator.go`, `app.go`, `Connect.tsx`, `Add-server.tsx`, `Settings.tsx` | кнопка «включить» поднимает VLESS-туннель, статистика/логи/трей работают |
| 4 | Поставка и обновление ядра | `core_update.go`, `.github/workflows/*`, NSIS, README | `sing-box.exe` докачивается и обновляется из GUI |
| 5 | Полировка | Clash API (пинг/urltest, per-connection), killswitch, split-tunneling по процессам | «как в v2rayN, только свой» |
| 6 (опц.) | Вариант B и/или C | `engine_singbox_lib.go`, удаление `*_wg.go` | один exe / единый стек |
