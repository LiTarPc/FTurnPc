# Диагностика

[Все разделы документации](README.md)

## Сначала соберите информацию

1. Запишите сборку FTurnPc, источник и версию FreeTurn, версию sing-box и серверного ядра, если известна.
2. Уточните тип профиля: WG, URI или sing-box JSON; режим relay и transport.
3. Снимите фильтры на странице логов и воспроизведите ошибку один раз.
4. Сохраните фрагмент или файл из `%AppData%\FTurnPc-singbox\logs`.
5. Удалите секреты перед отправкой: Client ID, ключи, UUID, пароли и ссылки звонков.

На странице логов есть поиск, фильтры источника/уровня и копирование видимых строк. С фильтрами часть контекста теряется. Дисковый лог сохраняет историю автоматических переподключений одной пользовательской сессии. Число файлов ограничено: важный лог скопируйте отдельно.

## Типичные ситуации

| Симптом | Что проверить |
| --- | --- |
| FreeTurn не найден | Имя и путь `.exe`, старые копии в `assets`/`PATH` |
| sing-box не найден | Наличие файла по [порядку поиска](cores.md#замена-sing-box) |
| sing-box слишком старый | Эта ветка требует не ниже `1.14.0` |
| Ошибка `sing-box check` | Версия, JSON/URI и параметры протокола; TUN ещё не обязан быть запущен |
| Долго «Подключение» | Ссылка звонка, captcha, peer, авторизация, обфускация, ошибки TURN/DTLS |
| DTLS готов, но ожидается TURN IP | Обнаружение TURN и `/32` маршрут; `direct` пока не поддержан |
| `server did not acknowledge client ID` | Новый клиент и сервер без ACK |
| TUN есть, но интернета нет | Ошибки после DTLS, серверный backend, DNS, proxy-протокол |
| Ошибка прав на TUN/маршрут | Запуск от администратора, конфликты других VPN |
| Ошибка замены ядра | Старый процесс, права на папку, клиент Windows x64, блокировка защитой Windows |

Отсутствие ошибки на экране не доказывает успех. При неудачной замене сначала [откатите один изменённый компонент](cores.md#откат).

## Подключено, но сайты не открываются

Проверьте последовательно:

1. Ошибки FreeTurn после готовности DTLS.
2. Совпадение режима, ключа и обфускации с сервером; разрешён ли Client ID.
3. Proxy/WG backend на VPS: FreeTurn-сессия не проверяет весь путь до интернета.
4. DNS sing-box: его изменение не исправляет резолвер API звонков FreeTurn.
5. Не уходит ли приложение напрямую по правилу обхода.
6. Конфликт с другим VPN, портом `9000` или маршрутизацией.

Меняйте один параметр за раз и переподключайтесь. Не отключайте антивирус/firewall целиком как стандартный способ диагностики.

## Счётчик трафика

Скорость и объём вычисляются по счётчикам Windows-интерфейса TUN текущей сессии, а не всего трафика компьютера. Базовое имя — `fturn-tun`; приложение отслеживает фактическое имя сессии.

- Обходящий VPN трафик может не попадать в TUN-счётчик.
- Байты TUN не обязаны совпадать с Ethernet/Wi-Fi: внешние накладные расходы TURN/DTLS учитываются иначе.
- Показания относятся к текущему подключению, не всей истории.
- После отключения активное обновление статистики прекращается.

Для проверки используйте приложение и ресурс, не добавленные в обход. Передайте заметный объём данных и сравните рост TUN-счётчиков.

Read-only проверка в PowerShell:

```powershell
Get-NetAdapter -IncludeHidden | Where-Object { $_.Name -like 'fturn-tun*' }
Get-NetAdapterStatistics -Name 'fturn-tun*'
```

Если имя отличается, используйте фактическое имя интерфейса сессии. При отсутствии данных проверьте создание TUN и состояние подключения.

## Маршруты после отключения

FTurnPc создаёт host routes к peer/TURN через физический адаптер и при штатном отключении удаляет маршруты своей сессии. Не удаляйте все маршруты, адаптеры или чужие VPN-конфигурации.

Read-only просмотр:

```powershell
Get-NetRoute -AddressFamily IPv4
```

Если сеть не восстановилась, сохраните логи и сведения о маршрутах. Изменять конкретный маршрут следует после определения назначения и владельца.
